# cleanup-orphan-branches

清理本地仓库里**远程已经不存在**的分支，以及它们绑定的 worktree。支持终端交互和网页勾选两种方式。

## 安装

```bash
./install.sh
```

软链到 `~/.local/bin/cleanup-orphan-branches`。需要 Python 3.8+（只用标准库）。

## 用法

```bash
cleanup-orphan-branches                  # 当前仓库，终端交互
cleanup-orphan-branches ~/repo           # 指定仓库
cleanup-orphan-branches --web            # 网页勾选删除
cleanup-orphan-branches --dry-run        # 只列出将要执行的命令
```

### 选项

| 选项 | 说明 |
|---|---|
| `--web` | 启动网页界面，在页面上勾选后批量删除 |
| `--dry-run` | 只列出将要执行的命令，不执行。与 `--web` 同时使用时，页面按钮变为「预览」 |
| `--port N` | 指定 Web 端口。被占用时自动回落随机端口并打印实际端口 |
| `--bind ADDR` | Web 绑定地址，默认 `0.0.0.0`（局域网可达） |
| `--no-fetch` | 跳过启动时的 `git fetch --prune`（默认执行，15 秒超时后按本地状态判定） |

## 判定规则

| 状态 | 含义 | 会被清理 |
|---|---|---|
| 无上游 | 从未设置 upstream | 是 |
| 远程已删除 | upstream 配置还在，但远程分支已删（`[gone]`） | 是 |
| 追踪其他分支 | upstream 名与本地名不同 | 否 |
| 正常 | 有 upstream 且存在 | 否 |

### 保护规则

以下分支会在页面上置灰、服务端拒绝删除，终端模式下也不会列入待清理项：

- `master` / `main` / `develop`
- 当前所在分支
- 有未推送 commit 的分支（`git rev-list --count <branch> --not --remotes` > 0）

**有未提交改动的分支不保护**——它照常可勾选删除，但会在列表里标记警告，web 模式下提供「查看改动」链接，可以先看清楚改了哪些文件、内容是什么再决定。

注意 `develop` 是硬编码的。如果你的仓库用别的名字作主干，需要改 `PROTECTED_BRANCHES`。

### 查看未提交改动

分支所在的 worktree 有改动时，列表该行会出现「查看改动」链接，点进去是一页只读视图：

- 改动文件清单（含 `M` / `??` 等状态）
- 完整 diff，按行高亮增删
- 未跟踪文件的内容也会列出（`git diff` 本身不含未跟踪文件，这里单独补读）

终端模式下，待删除清单里同样会列出改动文件（最多 10 个）。

页面路由是 `GET /diff?branch=<分支名>`，只在 web 模式可用。分支名做了 URL 编码与 HTML 转义。

## Web 模式

```
Web 服务已启动
  http://127.0.0.1:41297/
  http://192.168.110.17:41297/

注意: 服务无认证，同网段知道地址的人都能提交删除请求。
      操作完成后进程会自动退出。
```

页面是一张表，一行一个分支，附带状态、上游 ahead/behind、worktree 路径、最后提交时间作者、保护原因。孤儿默认勾选、默认只显示孤儿，可取消筛选勾选其它分支。

勾选后点「删除勾选的分支」，逐项执行，失败继续，最后在页面和终端同时输出汇总。服务处理完这一批就退出。

不想删任何东西时点「退出」：页面会请求关闭服务、清空页面并尝试关闭浏览器标签页，终端里的进程随即结束。已勾选的项直接丢弃。

### 页面路由

| 路由 | 说明 |
|---|---|
| `GET /` | 分支列表 |
| `GET /diff?branch=<名字>` | 该分支 worktree 的未提交改动 |
| `POST /delete` | 批量删除（`--dry-run` 时为 `POST /preview`） |
| `POST /quit` | 退出，不执行任何删除 |

**安全提示**：服务没有任何认证。知道 URL 的任何人在服务存活期间都能提交删除请求。只在可信局域网使用，用完即退（本工具本身就是一次性的）。

## 删除动作

每个分支按顺序执行：

1. 若有独立 worktree：`git worktree remove -f <path>`；失败则 `rm -rf` + `git worktree prune`
2. `git branch -D <name>`

一律用 `-D`（强制）。保护规则已经拦掉了会丢数据的分支，剩下的删除是用户明确勾选的结果。

## 已知限制

- 分支列表是启动时的快照。Web 页面删除后不刷新表格——服务本来就只处理一批。
- `--port` 被占用时静默回落随机端口，只打印实际端口，不中断。
- 无自动化测试。验证方式见 `docs/adr/0001-no-csrf-protection.md` 末尾。
